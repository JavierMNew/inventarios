2. DETALLE TÉCNICO POR REQUERIMIENTO

--------------------------------------------------------------------------------
REQUERIMIENTO 1: IMPLEMENTACIÓN DE CONTENEDORES PARA COMPONENTES WEB
--------------------------------------------------------------------------------
Estado: CUMPLIDO

¿Qué es y por qué se cumple?
Se implementó la tecnología de virtualización a nivel de sistema operativo (Docker) 
para empaquetar la aplicación web completa junto con su runtime, dependencias y 
archivos de configuración en una imagen ejecutable ligera e independiente de la plataforma.

¿Cómo se cumple en el proyecto?
- Dockerfile (Multi-stage Build):
  * Etapa 'base': Utiliza 'node:22-alpine' como imagen ligera base y activa pnpm v9.
  * Etapa 'deps': Copia package.json y pnpm-lock.yaml e instala dependencias.
  * Etapa 'builder': Ejecuta 'pnpm build' compilando la aplicación Astro SSR hacia el directorio '/dist'.
  * Etapa 'runner': Genera la imagen final de producción expuesta en el puerto 4321, ejecutando el servidor 'node ./dist/server/entry.mjs'.
- docker-compose.yml:
  * Orquesta el servicio 'inventarios-web', mapeando el puerto host 4321:4321.
  * Define reinicio automático ('restart: unless-stopped') y variables de entorno (PORT=4321, HOST=0.0.0.0).

--------------------------------------------------------------------------------
REQUERIMIENTO 2: SERVIDOR DE APLICACIONES (APP SERVER)
--------------------------------------------------------------------------------
Estado: CUMPLIDO

¿Qué es y por qué se cumple?
El Servidor de Aplicaciones es la capa encargada de procesar las peticiones HTTP, 
ejecutar la lógica de negocio, gestionar el middleware de seguridad/sesión y 
renderizar dinámicamente las vistas web en el servidor (SSR - Server-Side Rendering).

¿Cómo se cumple en el proyecto?
- Adaptador SSR Híbrido (astro.config.mjs):
  * Configurado con detección automática de entorno ('isVercel = Boolean(process.env.VERCEL)'), 
    permitiendo la ejecución tanto en contenedor Docker Node.js standalone como en Vercel Serverless.
- Lógica de Negocio y Controladores Tipados (Astro Actions):
  * Implementados en 'src/actions/index.ts' con validación Zod para procesar 
    las operaciones de empresas, colaboradores, inventarios y gastos.
- Middleware de Sesión y Autenticación (src/middleware.ts):
  * Intercepta todas las peticiones entrantes para verificar cookies de sesión 
    y proteger las rutas privadas '/app/[slug]/...'.

--------------------------------------------------------------------------------
REQUERIMIENTO 3: SERVIDOR DE BASE DE DATOS (DATABASE SERVER)
--------------------------------------------------------------------------------
Estado: CUMPLIDO

¿Qué es y por qué se cumple?
Se requiere un servidor de base de datos relacional y seguro que almacene 
de forma persistente la información de usuarios, empresas (tenants), miembros, 
productos e historiales de gastos con aislamiento estricto de datos.

¿Cómo se cumple en el proyecto?
- PostgreSQL Gestionado en la Nube (Supabase):
  * Se utiliza una instancia de base de datos PostgreSQL alojada en la nube mediante Supabase.
- Aislamiento Multi-Tenant con Row Level Security (RLS):
  * Las tablas 'empresas', 'miembros_empresa', 'productos' y 'gastos' cuentan con políticas RLS 
    activadas a nivel de motor de base de datos PostgreSQL.
  * Se definió la función PL/pgSQL 'obtener_rol_en_empresa' con privilegios 'SECURITY DEFINER' 
    para validar la pertenencia del usuario sin generar ciclos ni fugas de datos entre organizaciones.
- Patrón Request-Scoped Client Factory (src/lib/supabase.ts):
  * La función 'getSupabase(cookies)' crea un cliente de Supabase aislado por cada petición HTTP, 
    previniendo problemas de mezcla de sesiones en el servidor (session bleeding).

--------------------------------------------------------------------------------
REQUERIMIENTO 4: BALANCEO DE CARGAS (LOAD BALANCING)
--------------------------------------------------------------------------------
Estado: CUMPLIDO

¿Qué es y por qué se cumple?
El balanceo de cargas distribuye el tráfico de red de los usuarios entre múltiples 
instancias del servidor de aplicaciones para prevenir saturación y garantizar alta disponibilidad.

¿Cómo se cumple en el proyecto?
- Red Distribuida Vercel Edge Network (Anycast Load Balancing):
  * El despliegue activo en la nube hace uso del sistema de distribución de carga 
    de Vercel, el cual enruta dinámicamente el tráfico a través de una red Anycast 
    global hacia la función Serverless más cercana al usuario con menor latencia.
- Compatibilidad Local (Docker + Proxy Inverso):
  * El contenedor 'inventarios-web' expone el servicio en '0.0.0.0:4321', listo para 
    colocarse tras proxies inversos como Nginx, Traefik o HAProxy.

--------------------------------------------------------------------------------
REQUERIMIENTO 5: CERTIFICADOS DE SEGURIDAD (SSL/TLS / HTTPS)
--------------------------------------------------------------------------------
Estado: CUMPLIDO

¿Qué es y por qué se cumple?
Garantiza que toda la comunicación entre los usuarios y los servidores de aplicación 
y base de datos viaje cifrada a través de protocolos HTTPS / TLS 1.3.

¿Cómo se cumple en el proyecto?
- Encriptación SSL/TLS Automática en el Dominio:
  * El dominio publicado 'https://inventarios-seven.vercel.app/' cuenta con un certificado 
    de seguridad SSL/TLS válido de 256 bits proporcionado y gestionado automáticamente por Vercel/Let's Encrypt.
- Transmisión Cifrada de Datos (Capa de Aplicación):
  * Todas las conexiones hacia Supabase (Base de datos y Autenticación) utilizan 
    protocolos seguros HTTPS y WebSockets cifrados (WSS), requiriendo API keys y JWTs.

--------------------------------------------------------------------------------
REQUERIMIENTO 6: CONFIGURACIÓN DE DOMINIO PERSONALIZADO EN LA NUBE (DNS)
--------------------------------------------------------------------------------
Estado: CUMPLIDO

¿Qué es y por qué se cumple?
Se configuró e integró un nombre de dominio público accesible globalmente en internet 
que apunta hacia los servidores de infraestructura del proyecto.

¿Cómo se cumple en el proyecto?
- Dominio Público Activo:

    en tiempo real desde cualquier dispositivo del mundo.
